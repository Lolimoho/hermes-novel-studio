# 术语表

状态：M0 草案，待确认
适用范围：本项目全部产品文档、架构文档、API 契约、数据库命名

## 一、使用约定

1. **中文标准名**用于正文叙述；**标识符**用于 API、JSON 字段、数据库表名与列名，统一 `snake_case`。
2. 一个概念只有一个标准名。同义说法一律记入「禁用与替换」，不再并行使用。
3. 术语冲突时以本表为准，并回头修正相冲突的文档。
4. 新增术语先入本表，再进入其它文档。

## 二、作品结构

| 标准名 | 标识符 | 定义 | 不要理解为 |
|---|---|---|---|
| 作品 | `project` | 一部小说的整体，创作、版本、审批、审计的归属单位 | 软件项目 |
| 卷 | `volume` | 作品内的结构分段，含若干章。每卷有「核心功能」与「卷末状态」 | 弧线，或单纯的章节分组 |
| 章 | `chapter` | 最小创作单位与最小定稿单位，整数编号，从 1 开始 | 场景（scene） |
| 章节蓝图 | `chapter_plan` | 大纲精化版中的单章条目：主角小目标、冲突与转折、悬念钩子、出场人物、目标字数 | 正文，或整份大纲 |
| 弧线 | `arc` | 角色或情节跨章的成长曲线，由若干节点组成 | 卷（结构单位），或章节顺序 |
| 线索 | `thread` | 主线、支线、伏笔的追踪单位，记录埋设章、推进章、解决章 | 弧线，或章节 |
| 正文 | `content` | 作品的可读文本部分，由各章的草稿与定稿组成 | 蓝图、设定、大纲 |

## 三、创作文件

| 标准名 | 标识符 | 文件 | 产生阶段 | 性质 |
|---|---|---|---|---|
| 创意纲要 | `brief` | `brief.md` | 01 | 静态权威 |
| 故事大纲 | `outline` | `outline.md` | 02 | 静态权威，分骨架版与精化版 |
| 世界观 | `world` | `world.md` | 04 | 静态权威 |
| 风格规范 | `rules` | `rules.md` | 人工定义 | 静态权威 |
| 角色卡 | `character_sheet` | `tracking/characters/{角色名}.md` | 03 | 动态权威 |
| 进度台账 | `progress` | `tracking/progress.md` | 08 更新 | 动态权威 |

**静态权威**：定义后保持稳定，修改需回溯已写章节。
**动态权威**：随剧情推进持续更新。

> `outline` 指整份大纲文件；`chapter_plan` 指其中一章的条目。二者不可互换使用。

## 四、稿件状态

这是最容易混淆的一组，必须先分清三个维度：**创作状态**、**存储版本**、**内容来源**。

### 4.1 创作状态

| 标准名 | 标识符 | 文件 | 定义 |
|---|---|---|---|
| 未开始 | `not_started` | 无 | 蓝图已定，正文未写 |
| 草稿 | `draft` | `chXX-draft.md` | 已写出但未经人工定稿，可反复修改 |
| 定稿 | `finalized` | `chXX.md` | 人工批准、可对外发布，不可静默修改 |

状态流转：

```text
not_started --05 写作--> draft --07 定稿--> finalized
                          ↑   |
                          |   └--06 修订（仍是 draft，不改变状态）
                          └------- 修订后重跑 06
```

### 4.2 存储版本

| 标准名 | 标识符 | 定义 |
|---|---|---|
| 版本 | `revision` | 存储层的一次不可变快照，含 id、时间、作者、内容哈希。每次保存或批准产生一条 |

**关键区分**：`draft` / `finalized` 是**创作状态**，`revision` 是**存储概念**。一个草稿可以有多条 revision；一个定稿也保留其全部历史 revision。

### 4.3 内容来源

| 标准名 | 标识符 | 定义 |
|---|---|---|
| 候选稿 | `candidate` | AI 生成、尚未经人工接受的内容。可转为草稿，也可被丢弃 |

> 严禁把 `candidate` 与 `draft` 混用：候选稿是「来源」，草稿是「状态」。AI 产出的候选稿只有在人接受后才成为草稿。

### 4.4 三个易混词的定死

| 词 | 词性 | 含义 |
|---|---|---|
| 修订 | 动词 `revise` | 对草稿的修改动作（阶段 06），不产生新状态 |
| 修订稿 | 名词 `revised draft` | 修订后的草稿，状态仍是 `draft` |
| 版本 | 名词 `revision` | 存储层的一次快照，与「第几稿」不是同一件事 |

## 五、审批

| 标准名 | 标识符 | 定义 |
|---|---|---|
| 批准 | `approval` | 人对某条 `revision` 的确认动作，记录人、时间、被批准对象 |
| 已批准 | `approved` | 状态。只有被批准的 revision 才能成为正式事实的一部分 |
| 正式事实 | `canon` | 全部已批准的设定与章节所构成的事实集合，以 Postgres 为唯一权威 |
| 审批门 | `approval_gate` | 流程中必须人工确认的检查点，Agent 与自动化不可越过 |

> `canon` 是**集合概念**，不是单个对象。说「这条设定进入 canon」可以，说「这个 canon」不行。

## 六、执行

| 标准名 | 标识符 | 定义 |
|---|---|---|
| 运行 | `run` | 一次 AI 执行的完整记录：上下文来源、模型、输出、用量、状态、耗时 |
| 运行步骤 | `run_step` | 一次 run 内部的单步，对应一次生成或一次工具调用 |
| 任务 | `task` | 编排单位，可包含多个 run，可暂停、重试、退回、接管 |
| 会话 | `session` | 与 Agent 的连续上下文容器，不是作品数据的存储位置 |
| 工具调用 | `tool_call` | Agent 经领域工具执行的一次领域操作 |

**三者关系**：`task` 编排 → `run` 执行 → `run_step` 记录。`session` 只承载上下文，不承载作品事实。

## 七、集成

| 标准名 | 标识符 | 定义 |
|---|---|---|
| 配置档案 | `profile` | Hermes 侧的模型、技能、记忆配置集合。Studio 只读取与绑定，不复制其密钥 |
| 技能 | `skill` | 提示词与参考资产包（`skill/` 目录），不含可执行脚本 |
| 适配器 | `adapter` | Agent 接入的具体实现，统一遵循同一契约 |
| 记忆 | `memory` | Hindsight 中可检索的语义记忆，是检索材料，不是权威事实 |

## 八、禁用与替换

| 不要写 | 应写 | 原因 |
|---|---|---|
| 项目 | 作品 | 与软件项目混淆 |
| 修订版 / 修改版 | 修订稿 | 与 `revision`（版本）混淆 |
| 正式版 / 终稿 | 定稿 | 与 `approved` 混淆 |
| AI 稿 / 生成稿 | 候选稿 | 来源被误当成状态 |
| 章节文件 | 章节草稿 / 章节定稿 | 未标明状态 |
| 大纲（指单章时） | 章节蓝图 | 层级不同 |
| 角色档案 / 人设 | 角色卡 | 与 `character_sheet` 对齐 |
| 设定集 | 世界观 | 与 `world` 对齐 |
| 初稿（指状态时） | 草稿 | 「初稿写作」作为阶段 05 的名称可保留，状态一律称草稿 |

## 九、文件与状态映射

| 文件 / 存储 | 对应状态 | 说明 |
|---|---|---|
| 无文件 | `not_started` | 蓝图已定，未动笔 |
| 存储层临时区 | `candidate` | AI 产出未被人接受 |
| `content/chXX-draft.md` | `draft` | 每次保存生成一条 `revision` |
| `content/chXX.md` | `finalized` | 转正时记录的 `revision` 即批准对象 |

## 十、待定

以下术语尚未定案，进入对应里程碑前必须收敛：

1. **场景 `scene`** —— 当前为正文内隐式单位，是否建模为独立实体（影响审稿粒度与差异对比）。
2. **节拍 `beat`** —— 是否引入，或由 `chapter_plan` 的字段覆盖。
3. **卷与弧线的关系** —— 卷是结构单位、弧线是语义曲线；当前不建关联表，仅在 `outline` 中文字关联。
4. **候选稿是否落文件** —— 直接影响 M7 的恢复与审计设计，需在 M3 前定。
